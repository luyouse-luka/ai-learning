**答**：（原答：`summary: str, truncated: boolean, output_tokens: int, input_tokens: int, cost: float, model: str`
／`toUserMessage(err: any)` 在写的时候我使用了代码补全）

**☑\* 教练代填（09-18 ly 指定）。字段名你全对，错的是类型 —— TS 不是 Python：**

```ts
export interface SummarizeResponse {
  summary: string;        // str   → string
  truncated: boolean;     // bool  → boolean
  input_tokens: number;   // int   → number
  output_tokens: number;  // int   → number
  cost: number;           // float → number  ← TS 不区分整数小数，都是 number
  model: string;          // str   → string
}
```

**TS 只有一个 `number`**，没有 int / float 之分（底层都是 IEEE 754 双精度浮点）。
所以后端 Pydantic 的 `int` 和 `float` 到了 TS 这边**合并成同一个类型**，
契约的这一半天然比后端那一半"粗"一档 —— 想在前端区分整数小数，只能自己校验，类型系统不管。

⚠️ 这张映射表**逐字写在 `types/api.ts` 的 TODO 注释第 8 行**，是你自己填过的文件。
瓶颈 1「知道了没调用」**第 8 次**。

**`any` 已于 09-18 清掉（教练代改，ly 指定）**，改法和理由：

```ts
function toUserMessage(err: unknown): string {
  if (axios.isAxiosError<ApiError>(err) && err.response) { ... }
  return `网络异常，请检查后重试`
}
```

- **`any` → `unknown`**：`any` 是"关掉类型检查"，`unknown` 是"现在还不知道，用之前必须先收窄"。
  catch 到的东西本来就可能是任何东西（axios 错误 / 普通 Error / 被 throw 的字符串），`unknown` 才是诚实的类型。
- **`axios.isAxiosError<ApiError>(err)` 是类型守卫**（type guard）：
  它的返回类型写成 `payload is AxiosError<T>`，TS 看到这种签名就知道
  「这个函数返回 true 的话，`err` 在这个 `if` 里面就是 `AxiosError<ApiError>`」——
  于是 `err.response.status` 能点出来，而 `if` 外面 `err` 仍然是 `unknown`。
  **泛型 `<ApiError>` 不能省**：`isAxiosError` 的默认泛型是 `any`，省了等于把 any 从参数挪到了 data 上。
- 连带还掉 Day 4 的账：`ApiError.detail` 补成 `string | ValidationIssue[]`
  （422 的 detail 是数组，Day 4 砍 `ValidationIssue` 的理由是"现阶段无真实使用处"，现在有了）。
  422 分支因此要分形状取：`Array.isArray(detail) ? detail[0]?.msg : detail`

判据：`pnpm type-check` 通过；`pnpm exec eslint src/` **从 1 个 error 降到 0**；`grep -rn ": any" src/` 无命中。

### 差别 2 · 状态住在哪（DOM 是状态本身 vs DOM 是状态的投影）

```
原生版  setState(state, message) —— state 是个函数参数，函数一返回就没了。
        想知道「现在是什么状态」，只能去读 DOM：els.btn.textContent === "重试" ?
        —— DOM 就是唯一的状态存储，没有第二份

Vue 版  FileUploader.vue:25 const status = ref('idle')
        状态住在组件实例里，活到组件卸载。想知道现在什么状态就读 status.value，
        —— 从不去读 DOM。DOM 只是 status 的投影
```

**这条直接踩在你的老瓶颈 3 上**（「谁在维护它 / 它活多久」，已第 5 次）：

| 问题 | 原生版 | Vue 版 |
|---|---|---|
| 谁在维护状态？ | **没有"它"**，只有 DOM 上的痕迹 | `status` 这个 ref |
| 它活多久？ | `state` 参数：函数返回就没了 | 组件实例的生命周期 |

所以原生版有个隐患：**同一个状态被写在三个 DOM 属性上**（`btn.disabled` / `btn.textContent` /
`status.className`），三者可能不同步 —— 谁漏改一处就是"按钮还禁着但文字已经变回去了"。
Vue 版不可能出这个问题，因为它们三个都是从**同一个** `status` 推出来的。

#### ③ Vite 代理 —— **☑ 过，但有一处概念错**

「服务端转发」✅ 出现了，三句都在点上。

**概念错**：「被 CORS 拦截」—— **拦你的是同源策略，不是 CORS。**

- **大白话**：同源策略是门卫，CORS 是通行证制度。你被门卫拦下，不是被通行证拦下 ——
  **通行证是用来放行的。**
- **官方定义**：同源策略（Same-Origin Policy, SOP）是浏览器默认的安全限制；
  **CORS（Cross-Origin Resource Sharing，跨源资源共享）是一套放宽 SOP 的机制**，
  由服务器用 `Access-Control-Allow-Origin` 等响应头声明「我允许谁来」。
- **拆词**：Cross-Origin（跨源）+ Resource Sharing（资源共享）—— 名字里三个词没有一个是「拦截」。
- **三个例子**：
  1. 后端没有 CORS 头 → SOP 拦下 → 控制台报 `blocked by CORS policy`。
     **这句话是误解的唯一来源** —— 它说的是「CORS 策略没放行你」，不是「CORS 拦了你」
  2. 后端加 `Access-Control-Allow-Origin: *` → 放行，**不用代理也能通**（这是另一条路）
  3. Vite 代理 → **绕过**：浏览器压根不知道发生了跨源，SOP 根本没被触发
- **连回你的代码**：`vite.config.ts` 里你自己写的「跑腿的」那段注释是对的，概念名用错而已。
