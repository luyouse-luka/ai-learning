### 盲写结果

- 行数：59

- 修了几个 bug 才跑通：2
- 关键卡点：
1. print(delta, end="", flush=True) 语法问题，默认在末尾加换行。你现在是一个碎片一个碎片打，每片都换行的话，回复会竖着排成一列。设成空字符串 = 不换行，碎片才能接成一句话。flush=True：终端输出有缓冲区，像水池——攒够一定量或遇到换行才"冲"出去。你不换行了，缓冲区就会一直攒着，屏幕上什么都不显示，最后哗一下全出来 → 假流式。flush=True 是每片都立刻冲出去。

### 总结复盘代码盲写

1. tokens的计算，可以通过API文档中 stream_options 的include_usage true，然后计算chunk.usage.total_tokens
2. 对话直接KeyboardInterrupt时，后续的except KeyboardInterrupt处理，直接pop掉最后一条消息就行，而且while循环外也需要加上try包裹，防止程序中断崩溃
3. api调用的时候崩溃了，这条消息发送失败，提示一句，你可以重发，历史还在
    -那么就需要采用 try-except 包裹住整个 api 调用，如果失败了，就提示用户重试，并且外层也用try-except包住整个while循环，防止程序崩溃，优雅退出
4. 孤儿 user 消息，A 撤回 还是 B 存半截？
    -选 A（撤回那条 user）：history 回到中断前的干净状态。代价：你刚才那个问题在模型眼里从没发生过，AI 已经吐出来的半截内容也丢了。
    -选 B（半截 collected 存成 assistant）：history 是 user: 介绍一下python + assistant: Python 是一种高级、通用的...而不是像C语言那样（戛然而止）。下一轮你问"今天星期几"，模型看到的上下文里有一条话说到一半被掐断的自己的回复。
    选 A。 理由：宁可丢内容，不可让状态变脏。脏状态的 bug 是最难查的。直接pop弹出
